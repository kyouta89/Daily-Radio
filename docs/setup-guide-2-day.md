# AIラジオ 実装当日手順書

2026-09-29 · 高橋杏太

事前準備のチェックリストが埋まっている前提で、2時間で自分のラジオを動かします。作業はすべてブラウザで行い、ソフトのインストールはありません。STEP 1 から順に進めてください。途中で詰まったら最後の「つまずいたときの対処」を見てください。

## 当日のタイムテーブル

2人は**それぞれ自分のパソコンで並行して**進めます。待ち時間が出るのは STEP 5 だけです。

| 時間 | やること | 目安 |
| --- | --- | --- |
| 0:00〜0:10 | 事前準備の確認（キー9個がそろっているか） | 10分 |
| 0:10〜0:25 | STEP 1 自分のリポジトリを作る | 15分 |
| 0:25〜0:45 | STEP 2 キーを登録する | 20分 |
| 0:45〜1:05 | STEP 3 番組をカスタマイズする | 20分 |
| 1:05〜1:10 | STEP 4 カバー画像を置く | 5分 |
| 1:10〜1:30 | STEP 5 初回実行（うち15〜18分は待ち） | 20分 |
| 1:30〜1:50 | STEP 6 スマホで購読する | 20分 |
| 1:50〜2:00 | 予備・質問 | 10分 |

STEP 5 の待ち時間に、スマホでポッドキャストアプリを開いておくと STEP 6 が速くなります。

⚠️ **間に合わなそうなときは STEP 5 までを優先してください。** 番組が1本できていれば、翌日以降は毎朝自動で作られます。カスタマイズの続きやニュースの選定先の変更は、後日ゆっくりやれます。

## STEP 1 自分のリポジトリを作る（15分）

番組を作るプログラム一式を、自分の場所にコピーします。配布元のリポジトリのURLは当日共有します。

1. 配布元のリポジトリをブラウザで開く
2. 緑の **Use this template** ボタン → **Create a new repository** をクリック
3. **Repository name** を決める（半角英数字。例: `my-daily-radio`）
4. **Private** を選ぶ
5. **Create repository** をクリック
6. できたリポジトリの **Actions** タブを開き、**I understand my workflows, go ahead and enable them** を押して有効化する

手順6をやらないと自動実行がすべて止まったままになります。忘れやすいので必ず確認してください。

⚠️ **「Fork」ボタンは使わないでください。** 見た目は似ていますが、GitHub の仕様で**Forkしたリポジトリでは時刻指定の自動実行が動きません**。毎朝勝手に番組が作られるという一番大事な部分が死ぬので、必ず **Use this template** から作ってください。

Private リポジトリでも無料枠で十分です。自動実行は月 2,000 分まで無料で、1本の番組にかかるのは 15〜18 分、平日だけなので月 300〜400 分程度で収まります。

## STEP 2 キーを登録する（20分）

事前に控えたキーを、リポジトリの金庫（Secrets）に貼ります。ここに入れた値は他人からも自分からも二度と見えなくなるので、手元のメモは消さないでください。

1. リポジトリの **Settings** タブを開く
2. 左メニューの **Secrets and variables** → **Actions**
3. **New repository secret** をクリック
4. **Name** に下表の名前、**Secret** に値を貼って **Add secret**
5. 表の行数だけ繰り返す

| Secret の名前 | 貼るもの |
| --- | --- |
| `ANTHROPIC_API_KEY` | `sk-ant-` で始まるキー |
| `GEMINI_API_KEY` | `AIza` で始まるキー |
| `NOTION_API_KEY` | `ntn_` で始まるキー |
| `NOTION_DATABASE_ID` | Notion のデータベースID（32桁） |
| `CF_ACCOUNT_ID` | Cloudflare の Account ID（32桁） |
| `CF_R2_ACCESS_KEY_ID` | R2 の Access Key ID |
| `CF_R2_SECRET_ACCESS_KEY` | R2 の Secret Access Key |
| `CF_BUCKET_NAME` | バケット名（例: `my-radio`） |
| `CF_PUBLIC_URL` | 公開URL（例: `https://pub-….r2.dev`。**末尾の `/` は付けない**） |
| `R2_SECRET_PREFIX` | 自分で決める合言葉（下を参照） |

### R2_SECRET_PREFIX について

これが**番組を「自分だけのもの」にする合言葉**です。推測されにくい英数字 12 文字程度を自分で決めてください（例: `k7f9x2p3q1ab`）。ブラウザで「パスワード生成」と検索して作っても構いません。

**この文字列は必ずメモしておいてください。** STEP 6 の購読URLに使います。忘れると自分でも番組にたどり着けなくなります。

### 英語番組にする方だけ

もう1つ、同じ手順で Secret を追加します。

| Secret の名前 | 貼るもの |
| --- | --- |
| `SHOW_LANG` | `en` |

日本語番組の方は**登録不要**です（未登録なら日本語になります）。

⚠️ 名前は**大文字とアンダーバーまで正確に**入力してください。1文字でも違うと動きません。また、貼るときに**前後に空白や改行が入らない**よう注意してください。

## STEP 3 番組をカスタマイズする（20分）

編集するのは **`src/config.js` の 1 ファイルだけ**です。ブラウザ上で直接書き換えられます。

1. リポジトリの **Code** タブ → `src` フォルダ → `config.js` をクリック
2. 右上の**鉛筆アイコン**（Edit this file）をクリック
3. 下の4か所を書き換える
4. 画面右上の **Commit changes** → そのまま **Commit changes** を押す

| 書き換えるもの | 場所 | 例 |
| --- | --- | --- |
| 番組名・説明・配信者名 | `SHOW` の中 | `title: "朝のテック便"` |
| カテゴリ | `SHOW.category` | `Technology` / `Business` / `News` など |
| 天気の地域 | `LOCATION` | 緯度・経度と、読み上げる地名 |
| パーソナリティ2人 | `HOSTS` の A と B | 名前と性格の説明 |

**ダブルクォーテーション `" "` の中だけを書き換えてください。** カンマや記号を消すと動かなくなります。万一壊れても、編集履歴から元に戻せるので安心してください。

### パーソナリティの名前を決めるときのコツ

- `HOSTS.A` には**女性の声**、`HOSTS.B` には**男性の声**が日替わりで割り当てられます
- 名前は**短く、聴いてすぐ分かるもの**にする
- **番組でよく使う言葉と音が似た名前は避ける**。先行事例で「ミナ」という名前にしたところ、「ミナさん」と「皆さん」が紛らわしく聞こえる問題が起きました
- 英語番組の方は、ここも**英語で書いてください**。`SHOW_LANG=en` は台本を英語で書かせますが、このファイルの文字は自動翻訳されません

### 当日は触らないもの

ニュースの取得元（`src/axes.js`）は**当日はそのまま**にしてください。まず番組を動かすのが優先で、興味のある分野への差し替えは後日じっくりやれます。なお英語番組の場合、初期状態だと日本語のニュースサイトが混ざります（英語で解説はされます）。気になるなら後日、英語メディア中心に差し替えましょう。

## STEP 4 カバー画像を置く（5分）

事前に作った `thumbnail.png` を Cloudflare にアップロードします。

1. [dash.cloudflare.com](https://dash.cloudflare.com) → 左メニューの **R2** → 自分のバケットを開く
2. **Upload** ボタンを押し、`thumbnail.png` を選んでアップロード
3. 一覧に `thumbnail.png` という名前で並んでいれば完了

注意点は2つだけです。

- **フォルダは作らず、バケットの一番上の階層に置く**
- ファイル名が `thumbnail.png` 以外になっていたら、アップロード前にパソコン側で名前を直す

画像は後から差し替えられます。同じ名前で上書きアップロードすれば、数日でポッドキャストアプリ側の表示も入れ替わります。

## STEP 5 初回実行（20分・うち待ちが15〜18分）

ここで実際に1本目の番組を作ります。普段は毎朝自動で回りますが、初回だけ手動で回します。

1. リポジトリの **Actions** タブを開く
2. 左の一覧から **Daily Radio Automation** をクリック
3. 右側の **Run workflow** をクリック
4. **force_run** のチェックボックスを**オンにする**
5. 緑の **Run workflow** ボタンを押す
6. 数秒後に一覧に実行が現れるので、クリックすると進捗が見られる

**`force_run` をオンにする理由**：普段は「平日の朝だけ」「今日分が未作成なら」という安全装置が働いていて、そのままだと何もせずに終わることがあります。オンにすると土日祝でも強制的に作られます。

### 進捗の見方

ログに番号付きで進行が出ます。数字が進んでいれば正常です。

1. ニュースを取得中
2. 台本を執筆中（ここが一番長い）
3. 音声を生成中
4. Notion に保存中

**緑のチェックが付けば成功**です。赤い × になったら、最後の「つまずいたときの対処」を見てください。

### 成功したら確認すること

- Notion のデータベースに【Radio】付きのページができている
- そのページに、今日の要点と紹介記事のリンクが並んでいる
- Cloudflare のバケットに、**自分の合言葉のフォルダ**ができている

待ち時間の間に、スマホでポッドキャストアプリを開いておくと STEP 6 がスムーズです。

## STEP 6 スマホで購読する（20分）

あなたの番組のURLはこの形です。事前に決めた**合言葉**が間に入ります。

```
<公開URL>/<合言葉>/podcast.xml?v=2
```

例：`https://pub-abc123.r2.dev/k7f9x2p3q1ab/podcast.xml?v=2`

**URLは手打ちせず、メモからコピペしてください。** 合言葉は大文字・数字のゼロ・大文字のエルなどが混ざるため、手打ちするとほぼ間違えます。

### 追加の仕方

- **iPhone**：ポッドキャストアプリ →「ライブラリ」→ 右上の **・・・** → **URLから番組を追加** → 貼り付け
- **Mac**：ポッドキャストアプリ → メニューの **ファイル** → **URLから番組を追加**

### ⚠️ 最初から `?v=2` を付けてください

これは先行事例で実際にハマった落とし穴への対策です。**Apple は「追加に失敗したURL」を覚えてしまい、後から直しても同じURLを弾き続けます。** 末尾の `?v=2` は「別のURL」と認識させるためのもので、中身は同じファイルが返ります。付けたまま購読して問題ありません。

もし「フォローできません」「サーバまたは配信が見つからない」と出たら、**数字を `?v=3`、`?v=4` と変えて再試行**してください。

### フィードが正常かを確かめる方法

同じURLを **Safari** で開いてみてください。「**これはRSS配信のリンクです**」という案内が出れば、サーバー側は正常です（これはエラーではありません）。これが出るのにアプリで追加できない場合は、上の失敗キャッシュが原因です。

追加できたら完成です。翌日以降は**平日の朝6時に自動で新しい回が届きます**。各回の説明欄には、聴かなくても要点が分かるサマリーと紹介記事のリンクが入っています。

## つまずいたときの対処

失敗しても壊れません。直してもう一度 **Run workflow** を押せばやり直せます。

| 症状 | 原因 | 対処 |
| --- | --- | --- |
| Actions タブに何も出ない | STEP 1 の有効化忘れ | Actions タブで有効化ボタンを押す |
| 実行したのに何もせず終わる | `force_run` のチェック忘れ | オンにして再実行 |
| ログに Notion のエラー | データベースの「接続」忘れ | Notion で ・・・ → 接続 → インテグレーションを追加 |
| ログに 401 や authentication | キーの貼り間違い・前後の空白 | 該当の Secret を登録し直す（上書きOK） |
| ログに credit や billing | Anthropic の残高切れ | Billing でクレジットを追加購入 |
| ログに 429 や quota | Gemini の1日100回上限 | その日は待つ。翌日自動で回復 |
| 番組はできたがアプリに追加できない | Apple の失敗キャッシュ | URLを `?v=3` に変えて再試行 |
| カバー画像が出ない | ファイル名か置き場所違い | バケット直下に `thumbnail.png` で置き直す |

### 間に合わないときの割り切り方

この順番で優先してください。下に行くほど「後日でも全く問題ない」ものです。

1. **STEP 5 まで**（番組が1本できる）— ここまでいけば翌日から毎朝自動で回ります
2. **STEP 6**（購読）— 帰ってからでもできます
3. **番組名やパーソナリティの調整** — いつでも変更可。次の朝から反映されます
4. **ニュースの取得元の差し替え** — 慌てず後日

### 翌日以降について

- **平日の朝6時（日本時間）に自動実行**されます。土日祝は動きません
- 失敗したときは GitHub からメール通知が届きます。届いたら Actions タブのログを見て、上の表で当てはまるものを探してください
- 何日も番組が届かないのにメールも来ない場合は、Actions タブを見て実行自体が起きているか確認してください
