# Daily Radio 障害と対策（2026-07-17）

**7/17(金)の配信はできませんでした。** 原因が分かり、対策も入れてあります。7/21(火)から通常どおり戻る見込みです。

## 何が起きたか

音声合成（Gemini TTS）の**1日あたりの回数制限**に当たりました。

この番組は「ミナ:」「リク:」の**1セリフごとに音声APIを1回**呼びます。1本の番組は約94セリフあるので、**1本作るのに約94回**。ところが契約している枠は**1日100回**でした。つまり**1本作るだけで枠の94%を使う**、余裕6回という綱渡りの状態だったのです。

7/17はこうなりました:

1. 朝6:59の自動実行がハングし、4時間半後に手動で停止（この時点で枠を消費）
2. 11:35に手動で作り直そうとしたが、**枠はすでに使い切られていて1回も通らず失敗**

7/14・7/15までは別の音声サービス（OpenAI）を使っていて、Gemini に切り替えたのが7/17の未明。**つまりこの日が Gemini での初めての本番実行で、いきなり上限にぶつかった**格好です。

## なぜ原因がすぐ分からなかったか

エラーメッセージを**300文字で切り捨てて記録していた**ため、肝心の「どの制限に、いくつの上限で当たったか」がちょうど切れて消えていました。ログには「APIエラーらしい」までしか残っていませんでした。

## 対策

**① セリフごとに7秒の間隔を空けるようにしました**

回数制限には「1日100回」のほかに「1分あたり10回」もあり、従来は間隔ゼロで連射していたため開始1分で引っかかる状態でした。7秒空けることで両方に収まります。

→ **音声の生成に約11分かかるようになります**（全体で15〜20分）。ログが止まって見えても正常です。

**② エラーの全文を記録するようにしました**

次に何かあれば「どの制限に、上限いくつで、復帰まであと何時間」がログにそのまま出ます。

**③ 土日祝でも手動で回せるようにしました**

GitHubの画面から「強制生成」にチェックを入れて実行できます（検証用）。

## 音は変わりません

**声・ムード・喋り方・構成は今までどおりです。** 合成のやり方自体は変えていません。変わったのは「APIを呼ぶ間隔」だけです。

料金も変わりません（**1本あたり約$0.3、月およそ$6〜7**）。音声の長さで課金されるためで、回数を減らしても安くはなりません。

- 7/18〜7/20の3連休で自動検証します。7/21(火)から通常配信に復帰予定です

## 残っている課題

1本94回という構造自体は変わっていません（94/100で余裕6）。根本的には**2人分のセリフをまとめて一度に合成する**方式（94回→約7回）にすれば余裕が10倍以上になりますが、**喋りの間や抑揚の印象が変わる可能性がある**ため、聴き比べてから判断します。急ぎではありません。
