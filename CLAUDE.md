# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

- Run the full pipeline locally: `node index.js` (requires `.env` with all secrets below and `ffmpeg` installed).
- Force a run even if it's a weekend/holiday or today's Notion page already exists: `FORCE_RUN=true node index.js` (bypasses **both** the weekday-only guard and the "already ran today" skip).
- Install deps: `npm ci`.
- No linter or build step is configured. `npm test` is a placeholder that exits 1. There is **one** ad-hoc regression check that runs on plain node (no test framework): `node test/split-sections.js` — it asserts that `splitIntoSections` folds the fixture script (`test/fixtures/sample-script.txt`, a ~94-utterance episode) into ≤10 sections, none over 2500 chars, with no dropped utterances. It also covers `buildSections` (corner-based splitting). Run it after touching `parseDialogue`/`splitIntoSections`/`buildSections` in `audio.js`.
- `node dry-run.js` runs the **script-only** path (fetch news → generate script), skipping audio/Notion-save/R2, and writes the result to `output/dry-run-<timestamp>.txt`. It still needs `ANTHROPIC_API_KEY` plus `NOTION_API_KEY`/`NOTION_DATABASE_ID` (used only to fetch the 14-day exclusion set, same as the real run). Fast way to eyeball a generated script without spending TTS quota.
- Compare TTS engines on a fixed sample: `node ab-test/ab.js [openai|chirp3|gemini]` (`--list` dumps ja-JP Chirp3-HD voice names). See "TTS A/B harness" below.
- `list_models.py` is a standalone Python scratch script that lists available Gemini models. Not part of the pipeline.

The same entry point runs in CI via `.github/workflows/daily-radio.yml` (cron `0 21 * * 0-4` = **JST weekday mornings 06:00**, plus `workflow_dispatch`). CI installs `ffmpeg` via apt, sets `TZ=Asia/Tokyo`, and has `timeout-minutes: 60`.
### Required environment variables

`ANTHROPIC_API_KEY` (script generation), `GEMINI_API_KEY` (TTS), `NOTION_API_KEY`, `NOTION_DATABASE_ID`, `CF_ACCOUNT_ID`, `CF_R2_ACCESS_KEY_ID`, `CF_R2_SECRET_ACCESS_KEY`, `CF_BUCKET_NAME`, `CF_PUBLIC_URL`.

Optional overrides: `FORCE_RUN=true`, `ANTHROPIC_WRITER_MODEL` (default `claude-opus-4-8`), `ANTHROPIC_AUX_MODEL` (default `claude-haiku-4-5`), `GEMINI_TTS_MODEL` (default `gemini-2.5-flash-preview-tts`), `GEMINI_TTS_MIN_INTERVAL_MS` (default `7000` — TTS request pacing, see the quota note under `audio.js`), `GEMINI_TTS_SINGLE=true` (opt out of multi-speaker synthesis back to the one-request-per-utterance fallback — see `audio.js`), `HEALTHCHECK_URL` (dead-man's-switch ping target, see "Liveness monitoring" below; unset = no ping).

- **`GEMINI_API_KEY` is an AI Studio key** used to call the Gemini-TTS **`generativelanguage.googleapis.com`** REST endpoint directly — NOT the Vertex AI path (Vertex rejects API keys) and NOT the `@google/generative-ai` SDK.
- **Unused by the pipeline**: `OPENAI_API_KEY` / `OPENAI_TTS_MODEL` and the `openai` package are not touched by `index.js` or `src/*` (TTS moved OpenAI→Gemini; script moved Gemini→Claude) — but `openai` **is still a real dependency of `ab-test/ab.js`**, so don't remove it from `package.json` without deleting the harness. The workflow still passes `OPENAI_API_KEY` harmlessly. `@google/generative-ai` is genuinely dead — nothing requires it.
- `index.js` deletes `http_proxy` / `https_proxy` / `HTTP_PROXY` / `HTTPS_PROXY` at startup.

## Architecture

Single-shot Node.js script (no server, no persistent state) that runs the daily radio pipeline end-to-end. `index.js` orchestrates the stages; each `src/*.js` module is one stage. Cross-day state (which articles were used, whether today ran) lives in **Notion**, queried at startup — there is no local database.

The program is a **two-host dialogue radio show**. The script is written as alternating `話者名: セリフ` lines, and the audio stage re-reads those speaker labels to pick a voice per line. This contract between `script.js` and `audio.js` is the single most important invariant.

### Daily variation (`src/variant.js`)

`getDailyVariant(jstDateStr)` deterministically (date-seeded, so a given day is fixed/reproducible) picks **today's mood** (7 presets) and **voices** (female pool for ミナ, male pool for リク, from the Gemini/Chirp star-name voices). Each mood carries a `style` (TTS delivery/acting) and a `tone` (how the script is written). The variant is computed once in `index.js` and threaded into `script.js` (tone), `audio.js` (voice + style), and `notion.js` (recorded on the page). This is what makes each day sound different.

### Startup guards (`index.js`)

`index.js` computes the JST date, then — unless `FORCE_RUN=true`:
1. **Weekday-only skip**: if today (JST) is Saturday, Sunday, or a Japanese public holiday (`@holiday-jp/holiday_jp`), it exits early. (Weekends are also excluded at the cron level; the code guard covers holidays + manual dispatch + cron-delay edge cases.)
2. **Dedup skip**: if a Notion page `【Radio】YYYY-MM-DD` already exists, it exits.

It then fetches `fetchRecentArticleURLs` (URLs used in the last 14 days) and passes them as an exclusion set. **On any thrown error, `main` sets `process.exitCode = 1`** so the CI job goes red (a notification fires) instead of silently succeeding.

### Pipeline (`index.js` → `src/`)

1. **`rss.js` — fetchNews**: one `{name, selectionHint, items}` per axis. `items` is `{site, title, link, snippet, isoDate, ageDays}` (max 5/feed), **sorted newest-first** so stale feed ordering can't bury fresh news. `rss-parser` has a 15s timeout. Per-feed failures degrade to `[]`.
   - `fetchNews` rebuilds each axis object and now passes `priority: axis.priority` through (`src/rss.js:67`), so the `axis.priority` branch in `script.js` Phase 1 fires. (Historically `priority` was dropped here, making the ServiceNow freshness gate dead code; fixed in PR #21.)
2. **`script.js` — generateScript(axes, apiKey, excludedUrls, variant)**: four-phase Claude call (Anthropic SDK, `maxRetries:3`, `timeout:180s`). Every phase obeys `DIALOGUE_RULES` (speaker-labelled lines only) because `audio.js` parses it. The day's `variant.mood.tone` is injected into the writing prompts.
   - **Phase 0 (aux)** opening from live weather (`weather.js`) + "on this day" (`onThisDay.js`).
   - **Phase 1 (aux, parallel per axis)** selects 1 article as JSON. The list shows each item's **age (「◯日前」)**. If an axis has `priority: {keyword, maxAgeDays}` (currently ServiceNow / 7 days), a **code-side freshness gate** is *intended* to run: if a matching article ≤`maxAgeDays` old AND not in `excludedUrls` exists, candidates are restricted to those (keyword wins); otherwise keyword items are removed so a general article is picked. Combined with the 14-day dedup, this means "feature ServiceNow only when it's fresh AND not recently used." This gate is live (the `rss.js` `priority` pass-through was fixed in PR #21). A parse failure throws.
   - **Phase 2 (writer, sequential)** writes a 1200–1600 char dialogue per axis.
   - Fixed ending, then **Phase 3 (aux)** extracts tags + takeaway via `---TAGS_START---`/`---TAKEAWAY_START---` delimiters.
   - Returns `{script, tags, takeaway, linksRaw}`.
3. **`hosts.js` — HOST_A / HOST_B** (ミナ / リク): `name`, `persona`, `ttsInstructions`. **Shared by `script.js` and `audio.js`** (changing a `name` changes both what's written and what the parser matches). Note the `voice` field is now legacy/unused — actual voices come from `variant`.
4. **`audio.js` — generateAudio(script, GEMINI_API_KEY, dir, variant, dateStr)**: synthesizes via **Gemini-TTS** (`generativelanguage` REST API) using `variant.voiceA/voiceB` and a style from `variant.mood.style`. `sendTTSRequest` is the shared core (rate-limit pacing, retries, 429 daily/per-minute triage, PCM extraction); the two callers differ only in the request body they build. Gemini returns 24kHz/16-bit PCM; all parts are concatenated then **encoded to MP3 once via ffmpeg**, saved to `output/radio_YYYY-MM-DD.mp3` (JST), mixed with BGM, and uploaded via `r2.js`. Two synthesis paths:
   - **Default — multi-speaker (`geminiSynthSection`).** `buildSections(script, scriptSections)` picks the synthesis units (one request each). By default it uses the **`sections` array returned by `script.js`** — the natural blocks `[opening, each corner, ending]` — so **request boundaries land on corner transitions, not mid-corner**. (This was a real defect: char-based splitting dropped boundaries mid-conversation and the voice audibly drifted there — confirmed against the 2026-07-24 script.) Any block over 2500 chars is sub-split at utterance boundaries by `splitIntoSections` (the char-based splitter, also the fallback when no `sections` are passed — e.g. old callers). An episode is **~7 requests** (opening + 5 corners + ending) instead of ~94. Each block is one request carrying `multiSpeakerVoiceConfig` (2 speakers keyed by `HOST_A.name`/`HOST_B.name`); labels are normalized to a half-width colon so the API maps voices to labels. 2500 chars ≈ ~8 min audio ≈ ~9k output tokens, under the TTS session's 32k-token ceiling.
     - ⚠️ **Prosody caveat:** multi-speaker has per-request timbre variance, so the same host isn't perfectly identical across corners. Corner-based splitting **confines** the shift to natural transitions rather than eliminating it. Validated by listening to real episodes (2026-07-22…24): dialogue is natural/non-jarring; the residual variance is accepted as an incremental-improvement item.
   - **Fallback — single-speaker (`geminiSynthChunk`), behind `GEMINI_TTS_SINGLE=true`.** `parseDialogue` splits by `^(ミナ|リク)\s*[:：]`, each utterance is one request wrapped in a "you are a read-aloud machine, do not reply" prompt (Gemini otherwise 400s on short exclamations; the prompt is strengthened on retry). This is the pre-multi-speaker behavior; it warns if the job count exceeds the 100/day quota.
   - ⚠️ **The quota ceiling still shapes both paths.** Tier 1 allows **100 requests/day and 10 RPM** for `gemini-2.5-flash-preview-tts`. `MIN_REQUEST_INTERVAL_MS` (default 7000 ≈ 8.5 RPM, override via `GEMINI_TTS_MIN_INTERVAL_MS`) paces request *starts* so a run can't blow the 10 RPM cap in its first minute. Multi-speaker's ~7 requests clear this comfortably; the single-speaker fallback's ~94 requests do not (~94% of the daily quota, and re-running the same day is impossible). 429s are split by the API's own `RetryInfo.retryDelay`: >`HARD_QUOTA_RETRY_SEC` (300s) means the **daily** quota is gone → throw immediately with metric/limit (waiting hours is pointless); shorter means **per-minute** → sleep and retry.
   - **Never truncate the 429 body.** The metric name, limit, and retry delay live at the end of the message; an earlier 300-char `slice` hid exactly the part that identified the quota and cost a full investigation to recover.
   - **Cost is unaffected** by path choice — billed on output audio duration, ~$0.3/episode, ~$6–7/month.
5. **`bgm.js` — mixBGM(speechPath, seed)**: picks one track by date seed from a **pool** = `assets/bgm/*.mp3` **plus** the legacy `assets/bgm.mp3` (anchor, if present; currently absent so the run is pool-only); falls back to the anchor if the pool is empty. ffmpeg loops it under the speech at volume **0.09** with `amix duration=first` and **`-map "[mix]"` (audio-only output — prevents an embedded cover-art image from being looped forever by `-stream_loop`)**. The 19-track Pixabay pool was **loudness-normalized to −16 LUFS** (`-vn` + `loudnorm=I=-16:TP=-1.5:LRA=11`) in PR #23 so tracks don't jump in volume day-to-day; **normalize any new track the same way before dropping it in `assets/bgm/`**. Sources/licenses in `assets/bgm/CREDITS.md` (Pixabay Content License). Skips silently if no track or ffmpeg fails.
6. **`r2.js`**: Cloudflare R2 via the AWS S3 SDK. `uploadToR2`, `downloadExistingRSS` (null on 404), `uploadRSSToR2`.
7. **`rss_generator.js` — generateRSS**: rebuilds `podcast.xml` each run, preserving up to 29 prior `<item>`s. `durationSec` is measured from the final MP3 via `ffprobe` in `audio.js` (falls back to 0 if ffprobe is unavailable).
8. **`notion.js` — saveToNotion**: one page per run. Adds a **mood/voice callout** at the top (from `variant`), the takeaway, the link list, and the script split into ≤1800-char chunks. Uses the **data-sources API** (`getPrimaryDataSourceId` → `dataSources.query`).

### TTS A/B harness (`ab-test/`)

`ab-test/ab.js` synthesizes the fixed `ab-test/sample-script.txt` through OpenAI (`gpt-4o-mini-tts`), Google Cloud TTS (`Chirp 3: HD`), and Gemini-TTS, writing `output/ab_{openai,chirp3,gemini}.{mp3,wav}`. It is **independent of the pipeline** — no BGM, R2, or Notion — and exists to compare engines in isolation. It duplicates `parseDialogue` and the Gemini read-aloud prompt from `audio.js` on purpose (so the harness stays pinned while the pipeline evolves); they can drift, so don't assume changing one changes the other.

Its `GOOGLE_TTS_API_KEY` (Cloud TTS) is **a different credential from `GEMINI_API_KEY`** (AI Studio); each engine is skipped if its key is absent. Optional voice overrides: `CHIRP_VOICE_A`/`CHIRP_VOICE_B`, `GEMINI_VOICE_A`/`GEMINI_VOICE_B`.

### Cross-cutting notes

- **News axes live in `src/axes.js`** (`RSS_AXES`, 5 groups). Each is `{name, urls, selectionHint?, priority?}`. `priority: {keyword, maxAgeDays}` drives the code-side freshness gate (see Phase 1). The low-value ServiceNow community-announcement feed was removed. The hardcoded ending in `script.js` says "5つのコーナー".
- **Failure philosophy (deliberately mixed)**: peripheral enrichment (weather, on-this-day, individual RSS feeds, BGM, the exclusion set) degrades silently; anything that would ship a broken episode (article selection, TTS, R2, Notion) throws → `process.exitCode=1` → red job → notification. Preserve this split.
- **Liveness monitoring (dead-man's switch)**: a red job notifies, but that only fires when the job *runs*. GitHub disables scheduled workflows after 60 days of repo inactivity, and cron delivery is best-effort — a workflow that never runs is silent. `index.js` pings **Healthchecks.io** (`HEALTHCHECK_URL`) exactly once after `main()` settles: success (`""`) on normal completion **and on intentional skips** (holiday / already-ran — those don't set `exitCode`), `/fail` on error. The ping is best-effort (`pingHealthcheck`, 10s timeout, never throws, no-op if `HEALTHCHECK_URL` unset) so monitoring can't break the pipeline. Missing weekday ping → Healthchecks alerts from *outside* GitHub. Configure the check as cron `0 6 * * 1-5` TZ `Asia/Tokyo`, grace ~3h (absorbs cron delay + retry pacing); holidays self-cover because the job still runs and sends a success/skip ping. Setup steps in `docs/monitoring.md`. Keepalive (auto-disable *prevention*) was intentionally deferred — detection via Healthchecks is enough for now.
- **No-hang discipline**: every network call has a timeout — weather 15s, onThisDay 20s, rss-parser 15s, Gemini TTS 120s (per attempt, with retry), Anthropic SDK 180s — plus a job-level `timeout-minutes: 60`. When adding a `fetch`, give it an `AbortSignal.timeout`. The TTS stage's ~11 minutes of mostly-waiting is **intentional pacing** in the single-speaker fallback path, not a hang (see the `audio.js` quota note); the default multi-speaker path is much shorter (~7 requests). A normal end-to-end run is ~15–18 min, so don't lower `timeout-minutes` toward it.
  - `index.js` calls `main().finally(() => process.exit(process.exitCode || 0))` **on purpose**: the AWS SDK / TTS keep-alive sockets otherwise leave the event loop non-empty and the process hangs for many minutes after all work is done. The pipeline is fully sequential `await`, so reaching `finally` means everything has completed or thrown — exiting explicitly (preserving the exit code) is safe. This is the fix for the "job hangs for hours after finishing" bug.
- **Schedule**: JST weekday mornings only. Cron `0 21 * * 0-4` (UTC Sun–Thu 21:00 = JST Mon–Fri 06:00) excludes weekends; the `index.js` guard additionally skips Japanese holidays. `workflow_dispatch` runs anytime (holiday guard still applies unless `FORCE_RUN`).
- **Ordering**: Notion save happens after R2 upload; RSS `existingXML` is fetched before the new audio upload, then the whole feed is re-uploaded as `podcast.xml`.
- **Date handling**: JST is UTC+9h (`audio.js`, `rss_generator.js`, `onThisDay.js`, `index.js`). Notion's page title relies on `TZ=Asia/Tokyo` (set in CI). Keep the offset consistent.
- **`output/` is local-only scratch** (gitignored, alongside `.env`, `node_modules/`, `.tmp.driveupload/`); R2 is the source of truth for distribution.
- **`docs/release-notes/YYYY-MM-DD.md`** are Japanese, non-technical summaries written for the listener/owner when pipeline behavior changes audibly (dedup, axis reshuffles, opening accuracy) — they explain the *effect on the show*, not the diff. Add one when a change alters what the episode sounds like.
